# ТЗ — учет минут распознавания

## 1. Назначение

Реализовать прототип управленческого учета предоплаченных минут распознавания речи поверх базового ядра BaSYS.

Модуль должен использовать существующие справочники `company` и `counterparty`, не создавая дублей организации и клиента.

## 2. Сценарии

### 2.1. Покупка пакета минут

Пользователь создает операцию `recognition_package`.

Обязательные данные:

- организация;
- клиент;
- дата;
- сумма оплаты.

Система рассчитывает:

- цену минуты по сумме единовременной оплаты;
- количество минут пакета.

Правила тарифа:

- меньше 100 000 руб — 2 руб/мин;
- от 100 000 до 299 999 руб — 1 руб/мин;
- от 300 000 руб — 0.5 руб/мин.

При сохранении операция формирует приход в регистр `recognition_minutes`.

### 2.2. Загрузка месячного расхода

Пользователь создает операцию `recognition_usage`, прикрепляет Excel-файл и нажимает команду `load_from_file`.

Минимальная структура Excel:

| Клиент | Минуты |
|---|---:|
| ООО Пример | 30000 |

Строки загружаются в табличную часть `items`.

### 2.3. FIFO-расчет списания

Пользователь нажимает команду `calculate_fifo` в операции `recognition_usage`.

Команда:

- читает остатки регистра `recognition_minutes` по организации;
- исключает старые движения текущей операции по `object_uid`, если операция уже сохранялась;
- по каждой строке расхода списывает минуты с пакетов клиента в порядке даты пакета;
- при нехватке пакетов добавляет перерасход по тарифу 2 руб/мин;
- заполняет табличную часть `write_offs`.

При сохранении операция формирует расходные записи регистра `recognition_minutes` из строк `write_offs`.

### 2.4. Акт

В первой версии акт моделируется строками `write_offs` в операции расхода. Эти строки содержат клиента, пакет, тариф, минуты, сумму и признак перерасхода. Печатная форма или отдельный отчет добавляются следующим блоком после проверки базового сценария на стенде.

## 3. Metadata

Создать:

- `operation/recognition_package` — покупка пакета минут;
- `operation/recognition_usage` — месячный расход минут;
- `records/recognition_minutes` — регистр минут;
- `workflow/load_rec_usage_excel` — загрузка Excel в расход;
- команды `load_from_file` и `calculate_fifo` на операции расхода.

Обновить:

- `system/dataTypes.json` — добавить локальные типы для новых операций, потому что `operation` является reference-kind.

Не создавать:

- формы списка/редактирования;
- отдельные справочники клиентов;
- печатную форму акта;
- ручные пункты меню, потому что меню операций и регистров использует `AutoFill`.

## 4. Acceptance

Минимальная проверка на стенде:

1. Импортировать `records/recognition_minutes`.
2. Импортировать `operation/recognition_package`.
3. Импортировать `workflow/load_rec_usage_excel`.
4. Импортировать `operation/recognition_usage`.
5. Создать клиента в `counterparty` и организацию в `company`, если их нет.
6. Создать пакет на 50 000 руб: цена 2, минуты 25 000.
7. Создать пакет на 150 000 руб: цена 1, минуты 150 000.
8. Создать расход на 30 000 минут.
9. Нажать `calculate_fifo`.
10. Проверить строки списания: 25 000 минут по 2 руб и 5 000 минут по 1 руб.
11. Сохранить расход и проверить записи регистра.
12. Создать расход больше остатка и проверить строку перерасхода по 2 руб/мин.

## 5. Ограничения первой версии

- Excel-сопоставление клиента зависит от поведения BaSYS для reference-полей в `excel_mapping`; если автоматическое сопоставление по названию не сработает, файл нужно будет грузить с идентификатором клиента или добавить отдельный workflow сопоставления.
- Печатная форма акта не создается в этом блоке.
- Перепроведение задним числом требует повторного запуска `calculate_fifo` в последующих расходах.
