# Методика решения — Речевая аналитика

## 1. Бизнес-задача

Компания "Речевая аналитика" продает клиентам предоплаченные минуты распознавания речи. Клиент может оплатить несколько пакетов в разное время и по разным тарифам. Каждый пакет создается по факту единовременной оплаты, а цена минуты зависит от суммы этой оплаты.

Тарифы:

| Сумма единовременной оплаты | Цена минуты |
|---|---:|
| До 99 999 руб включительно | 2 руб/мин |
| 100 000-299 999 руб | 1 руб/мин |
| От 300 000 руб | 0.5 руб/мин |

Ежемесячно клиент расходует фактическое количество минут распознавания. Эти минуты должны списываться с оплаченных пакетов по FIFO: сначала самый ранний доступный пакет, затем следующий. Если оплаченные пакеты закончились, перерасход разрешается и учитывается по максимальному тарифу 2 руб/мин.

В конце месяца по каждому клиенту нужно сформировать акт с количеством израсходованных минут и суммой, сгруппированной по тарифам.

## 2. Цель прототипа

Прототип должен показать предпринимателю архитектуру управленческого учета минут и будущие точки интеграции. Первая версия моделируется без программиста и должна быть достаточно простой для проверки сценария на стенде BaSYS.

Прототип должен уметь:

- хранить клиентов;
- фиксировать оплаты клиентов как пакеты минут;
- рассчитывать цену минуты и объем пакета по сумме оплаты;
- загружать фактические минуты из Excel;
- списывать минуты с пакетов по FIFO;
- переносить остатки минут бессрочно;
- фиксировать перерасход по тарифу 2 руб/мин;
- формировать акт за месяц с минутами и суммой по тарифам.

## 3. Использование базового ядра

Текущая базовая учетная модель покрывает часть задачи и не должна дублироваться отраслевым модулем.

Использовать из ядра:

- `company` — собственная организация, для прототипа компания "Речевая аналитика";
- `counterparty` — клиенты;
- `bank_account` — расчетные счета;
- `money_receipt` — факт поступления денег, если в текущей реализации это уже доступно;
- `settlement_records` и `money_records` — для общего денежного и расчетного контура, если модуль будет связан с оплатами.

Отраслевой модуль не должен создавать собственные аналоги клиента, организации или банковского счета.

## 4. Предлагаемые объекты модуля

### 4.1. Операция покупки пакета минут

Черновое техническое имя: `recognition_package_purchase`.

Назначение: зафиксировать единовременную оплату клиента и создать пакет минут с конкретным тарифом.

Основные поля:

- организация;
- клиент;
- дата оплаты;
- сумма оплаты;
- цена минуты;
- количество минут в пакете;
- основание оплаты или ссылка на поступление денег;
- комментарий.

Расчет:

- если сумма оплаты меньше 100 000 руб, цена минуты 2 руб;
- если сумма оплаты от 100 000 до 299 999 руб, цена минуты 1 руб;
- если сумма оплаты от 300 000 руб, цена минуты 0.5 руб;
- количество минут = сумма оплаты / цена минуты.

Вопрос для будущего ТЗ: считать ли границу "до 99 999" строго до 99 999 руб или меньше 100 000 руб. Для прототипа использовать правило "меньше 100 000 руб".

### 4.2. Операция расхода минут за период

Черновое техническое имя: `recognition_usage`.

Назначение: зафиксировать фактический расход минут клиента за месяц и разложить его по пакетам и тарифам.

Основные поля:

- организация;
- клиент;
- месяц или период;
- общее количество минут из Excel;
- строки списания по пакетам и тарифам;
- комментарий.

Логика проведения:

- получить остатки пакетов клиента в порядке даты покупки;
- списать минуты с самого раннего пакета;
- если пакет закончился, перейти к следующему;
- если оплаченные пакеты закончились, создать строку перерасхода по цене 2 руб/мин;
- сформировать движения расхода минут в регистр.

### 4.3. Регистр учета минут

Черновое техническое имя: `recognition_minute_records`.

Назначение: хранить приходы, расходы, остатки и перерасходы минут.

Аналитики:

- период;
- организация;
- клиент;
- пакет минут;
- цена минуты;
- источник движения.

Ресурсы:

- количество минут;
- сумма.

При покупке пакета регистр получает приход минут. При месячном расходе получает расход минут по конкретным пакетам или перерасход по тарифу 2 руб/мин.

### 4.4. Импорт фактических минут из Excel

На первом этапе фактические минуты должны загружаться из Excel. Минимальная структура файла:

| Клиент | Месяц | Минуты |
|---|---|---:|
| ООО Пример | 2026-05 | 30000 |

В будущем файл может содержать дополнительные измерения: проект, пользователь, дата, источник распознавания. В прототипе детализация фиксируется на уровне клиента и месяца, а в акте результат группируется по тарифам после FIFO-списания.

### 4.5. Акт за месяц

Акт должен показывать фактически израсходованные минуты и сумму по тарифам.

Минимальные поля акта:

- организация;
- клиент;
- месяц;
- тариф;
- количество минут;
- сумма;
- итог минут;
- итог сумма.

Пример строк акта:

| Тариф | Минуты | Сумма |
|---|---:|---:|
| 2 руб/мин | 25 000 | 50 000 |
| 1 руб/мин | 5 000 | 5 000 |
| Итого | 30 000 | 55 000 |

Если есть перерасход, он показывается отдельной строкой по тарифу 2 руб/мин или с пометкой "Перерасход".

## 5. Ключевой сценарий

1. Клиент платит деньги.
2. Система создает пакет минут с тарифом по сумме единовременной оплаты.
3. Остаток пакета хранится до полного расходования, без срока сгорания.
4. Раз в месяц загружается Excel с фактическими минутами по клиентам.
5. Система списывает минуты FIFO с оплаченных пакетов.
6. Если пакеты закончились, система фиксирует перерасход по 2 руб/мин.
7. В конце месяца формируется акт с группировкой по тарифам.

## 6. Интеграции

Минимум для прототипа:

- Excel-импорт фактических минут из системы распознавания;
- ручное или полуавтоматическое создание пакетов по оплатам.

Будущие интеграции:

- банк или платежная система для автоматического создания пакетов по поступлениям денег;
- API системы распознавания для загрузки фактических минут без Excel;
- генерация PDF/Excel актов;
- отправка актов клиентам по email или через ЭДО;
- выгрузка данных в бухгалтерию.

## 7. Методические решения

1. Тариф определяется по каждой единовременной оплате, а не по сумме оплат за период.
2. Каждый платеж создает отдельный пакет минут.
3. Пакеты списываются FIFO.
4. Остатки минут переносятся бессрочно.
5. Перерасход разрешен и оценивается по максимальному тарифу 2 руб/мин.
6. Фактические минуты поступают через Excel-импорт.
7. Акт показывает минуты и сумму, сгруппированные по тарифам.

## 8. Методические риски

- Юридический акт на сумму списанных минут может конфликтовать с бухгалтерской моделью авансов. Для управленческого прототипа это допустимо, но для юридически значимого документооборота нужно разделить оплату как аванс, оказание услуги как закрытие аванса и перерасход как задолженность.
- Если оплаты будут автоматически загружаться из банка, потребуется правило сопоставления платежа с клиентом и назначением платежа.
- Если Excel содержит клиентов с отличающимися названиями, нужен механизм сопоставления строк Excel с `counterparty`.
- Если задним числом изменить оплату или расход, потребуется правило перепроведения FIFO и пересчета актов.
- Группировка акта по тарифам скрывает конкретные пакеты. Это удобно клиенту, но для внутреннего аудита может понадобиться расшифровка по пакетам.

## 9. Граница первой версии

Входит:

- учет пакетов минут;
- FIFO-списание;
- бессрочные остатки;
- перерасход по 2 руб/мин;
- Excel-импорт месячных минут;
- акт по клиенту за месяц с группировкой по тарифам.

Не входит:

- полноценная бухгалтерия авансов;
- автоматическая банковская интеграция;
- API-интеграция с системой распознавания;
- ЭДО и автоматическая отправка актов;
- проекты, пользователи и детализация по дням;
- сложная биллинговая политика, скидки и индивидуальные тарифы;
- сроки действия пакетов и сгорание минут.
