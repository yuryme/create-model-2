# Reference — экспорт действующей системы BaSYS

Здесь лежит **read-only** референсный корпус: полный экспорт действующей системы BaSYS, который AI-ассистент использует как:

- источник UID видов и типов данных (для генерации новых объектов);
- источник реальных паттернов (как сделана работающая операция, регистр, отчёт);
- образец стиля именования и структурирования метаданных в этом проекте.

## Правила работы

1. **`reference/` — read-only.** Никогда не редактировать файлы внутри. Если нужна свежая выгрузка — пересоздать корпус заново.
2. **При генерации новых объектов** в `project/metadata/`:
   - Открывать соответствующий `INDEX-<kind>.md` и искать аналог по `Title`/`Memo`.
   - Если найден — открыть `reference/metadata/<kind>/<name>/<kind>.<name>.json` через `Read` и брать оттуда `MetaObjectKindUid`, `DataTypeUid` и структурные паттерны.
3. **UID объектов не копировать.** Каждый новый объект получает свой UID при импорте в BaSYS. Из референса берутся только UID **видов** (`MetaObjectKindUid`) и **типов** (`DataTypeUid`).
4. **Имена объектов на кириллице — допустимы.** В этой выгрузке часть объектов имеет `Name` на русском (`акт_монтаж_ме`, `карточка_договора` и т.д.). Это работает в BaSYS и не считается ошибкой. См. ADR в `project/docs/decisions.md`.

## Регенерация INDEX

При замене содержимого `metadata/` на свежую выгрузку — пересобрать `INDEX*.md`. Скрипт `build_reference_index.py` (если сохранён в корне workspace) делает это одной командой. Если удалён — попросить AI-ассистента: «обнови INDEX в reference/».
