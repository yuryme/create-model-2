# Отчёты и Панели данных (`data_view`)

**Supporting-файл скилла `basys-metadata`.** Открывать при работе с отчётами/дашбордами/визуализацией. Основной файл скилла — `SKILL.md`.

**Первоисточник:** `basys-docs/ru/reporting/dataView.md`.

## Когда применять `data_view`

Основной вид метаданных для отчётов, дашбордов, графиков, таблиц, KPI, гейджей и сводных таблиц — **`data_view` (Панель данных)**.

Когда пользователь просит любой отчёт/дашборд/визуализацию — **по умолчанию создаём `data_view`**, если он явно не попросил иное (`customreport`, `excel_report`).

## Размещение файлов

- У вида `data_view` флаг `StoreData = false`, поэтому файл настроек валидируется по `project/metadata/system/schemas/dataViewSettings.schema.json` (в `$schema` — правильный относительный путь).
- **Settings-файл:** `project/metadata/data_view/{name}/data_view.{name}.json`.
- **Скрипты источников данных** — отдельные `.bjs`-файлы в той же папке: `data_view.{name}.data_source.{dataSourceName}.bjs` (например, `data_view/nomenclature_balance/data_view.nomenclature_balance.data_source.rows.bjs`).
- Верхний уровень — стандартные поля метаобъекта (`Uid`, `Name`, `Title`, `Memo`, `IsActive`, `Version`) плюс три коллекции: `DataSources`, `Filters`, `Indicators`.
- У `data_view` флаг `IsReference = false` — запись в `system/dataTypes.json` **не нужна** (см. SKILL.md раздел 8.11 про условие).

## Построение отчёта — три шага

1. **Определить индикаторы** — тип, количество, расположение — исходя из запроса пользователя (см. раздел «Индикаторы» ниже). Что-то неясно — **спросить**, не угадывать.
2. **Описать источники данных** — одну или несколько записей `DataSources`, дающих данные нужным индикаторам.
3. **Связать каждый индикатор** с источником через `DataSourceUid` и сконфигурировать его специфические поля.

## Источники данных

Каждая запись `DataSources` в JSON имеет поле `Expression`, в котором указано **имя файла** соответствующего `.bjs`-скрипта (не тело скрипта). Скрипт — отдельным файлом в той же папке.

### Шаблон имени файла

`data_view.{objectName}.data_source.{dataSourceName}.bjs`

Пример — для data_view `nomenclature_balance` с источником `rows`:
- В JSON (`Expression`): `"data_view.nomenclature_balance.data_source.rows.bjs"`
- Файл скрипта: `data_view/nomenclature_balance/data_view.nomenclature_balance.data_source.rows.bjs`

### Контракт скрипта

Скрипт **обязан `return`-ить значение**:

- `DataTable` (или массив строк) — для табличных индикаторов (`pv_data_table`, `bs_pivot`) и графиков (`pv_bar_chart`, `pv_line_chart`, `pv_pie_chart`, `pv_donut_chart`);
- Скаляр (число/строку) или объект — для `bs_value_indicator` и `bs_gauge_indicator`.

При создании нового источника AI должен создать **обе стороны**: запись в `DataSources` JSON-а (с `Expression = "<имя файла>"`) **и** `.bjs`-файл с телом скрипта.

### Правила

- Для доступа к БД — **QueryBuilder** (`from('kind.name')...query()`), а не обычный JS. См. `basys-docs/ru/calculations/queryBuilder.md`.
- В контексте скрипта источника всегда доступны две неявные переменные:
  - **`_filters`** — текущие значения фильтров панели (если они есть в `Filters`). Передавать в запросы через `.parameter()`.
  - **`_data`** — результаты **других** источников этой же панели, доступные по `Name` (например, `_data.contracts`). Один источник может строиться поверх результата другого; платформа автоматически определяет порядок выполнения по использованию.
- У каждого источника — осмысленный `Name` (snake_case латиницей): он становится ключом в `_data`, последним сегментом имени `.bjs`-файла, и на него ссылаются индикаторы.
- Заполнять `Memo` — что возвращает источник.
- Для табличных источников, питающих таблицы/сводные/графики со ссылочными полями — использовать `.getDisplays()` при запросе, чтобы получить отображаемые значения как `<column>_display`. При группировке (`groupBy`) включать и `<column>`, и `<column>_display`.

## Индикаторы

Каждая запись `Indicators` — это один визуальный компонент. Тип определяется парой `KindUid` / `KindName`:

| Тип | KindName | KindUid |
|---|---|---|
| Индикатор значения | `bs_value_indicator` | `a876f44f-ebad-4e0c-8c75-a3b6df047367` |
| Индикатор-шкала (Gauge) | `bs_gauge_indicator` | `3920c90c-91f2-4598-a5d8-f4931974e578` |
| Гистограмма | `pv_bar_chart` | `19ab8886-cd18-4c06-aff0-5b010d4b891a` |
| Линейный график | `pv_line_chart` | `d5f9a3c4-7e6b-4cad-bf8a-3b4c5d6e7f8a` |
| Круговая диаграмма | `pv_pie_chart` | `b3d7e1a2-5c4f-4a8b-9d6e-1f2a3b4c5d6e` |
| Кольцевая диаграмма | `pv_donut_chart` | `c4e8f2b3-6d5a-4b9c-ae7f-2a3b4c5d6e7f` |
| Таблица | `pv_data_table` | `bd4b0526-449e-4351-85d1-b18a6aafa1b8` |
| Сводная таблица | `bs_pivot` | `65dd8c74-5337-4e35-bfab-24100f94b2b5` |

> ⚠️ Эти UID — **из чужой выгрузки** (заимствованы из Cursor-rules). Перед использованием **обязательно свериться** с нашей `project/metadata/system/kinds/kind.data_view.json` или с конкретной `data_view`-панелью в нашей или чужой системе. В разных инсталляциях BaSYS UID одного и того же вида/индикатора могут отличаться.

### Общие поля индикатора

`Uid`, `Name`, `Title`, `Memo`, `Order`, `Height`, `IsActive`, `DataSourceUid`, `RenderSettings`.

Специфические поля (оси, датасеты, колонки, уровни, строки/колонки/значения сводной...) — по соответствующим `*IndicatorDto` определениям в `dataViewSettings.schema.json`.

### Размещение на сетке (`RenderSettings`)

Компоненты размещаются на **12-колоночной сетке**:

- Предпочитать предустановленные подсказки:
  - `WidthHint` — `3` (Small), `6` (Half), `8` (Wide), `12` (Full).
  - `OffsetHint` — `0` (None), `3` (Small), `6` (Half), `8` (Wide).
- Если подсказка задана — числовые `Width` / `Offset` оставлять `0`.
- Для произвольного значения — поставить hint = `-1` (Custom) и явное число в `Width` или `Offset`.
- Индикаторы автоматически переносятся на следующую строку, когда `Offset + Width` превышает 12.

### Выбор типа, количества и компоновки

- Тип/количество/расположение — из запроса пользователя. **Не очевидно — спросить.**
- **Правило одиночного отчёта:** если пользователь говорит про отчёт в единственном числе («сводная таблица», «табличный отчёт», «круговая диаграмма») — на панели **ровно один** индикатор соответствующего типа, размером `WidthHint = 12` (Full).
- **Правило единственного заголовка:** если на панели один индикатор — оставлять его `Title` пустым (`""`); заголовком служит `Title` самой панели. Для нескольких индикаторов — у каждого внятный `Title`.

### Гигиена индикаторов

- У каждого нового индикатора — свежий `Uid`, осмысленный `Name` (snake_case латиницей), заполненный `Memo`.
- `IsActive = true`, если пользователь не попросил скрыть.
- Для `pv_data_table`, `bs_pivot` и графиков, показывающих ссылочные поля: источник должен использовать `.getDisplays()`, а индикатор — ссылаться на колонки `*_display` там, где нужны человекочитаемые подписи.
