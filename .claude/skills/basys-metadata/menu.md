# Меню (`menu`)

**Supporting-файл скилла `basys-metadata`.** Открывать при работе с навигационными меню. Основной файл скилла — `SKILL.md`.

**Первоисточник:** `basys-docs/ru/metadata/menu.md`.

## Что такое меню в BaSYS

**Меню** — метаобъект вида `menu`, описывающий **навигационное дерево** боковой панели приложения. Рендерится компонентом [PrimeVue MegaMenu](https://v3.primevue.org/megamenu/) в **вертикальной** ориентации, поэтому модель повторяет иерархию MegaMenu: корневая группа → колонки → подгруппы → ссылки.

Метаобъект `menu` **не хранит** пользовательских данных и **не использует** пользовательских форм — только структуру навигации.

В одном приложении может быть **несколько активных `menu`-объектов**. Сервер при построении бокового меню обходит **все активные** меню, фильтрует по правам пользователя и сливает видимые группы в один список. Это позволяет разнести навигацию по подсистемам/ролям/модулям и управлять ими независимо.

## Размещение файлов

- У вида `menu` флаги `StoreData = false` и `IsReference = false` → settings-файл валидируется по `system/schemas/menuSettings.schema.json` (`$schema` обычно `../../system/schemas/menuSettings.schema.json`). Запись в `system/dataTypes.json` **не нужна**.
- У вида **нет** `StandardColumns`, `Header`, `DetailTables`, `Commands`, `RecordsSettings`, `Forms`.
- Settings-файл: `project/metadata/menu/{name}/menu.{name}.json`.
- Имя папки и `{name}` в имени файла должны совпадать с `Name` метаобъекта.
- У `menu` **нет** companion `.bjs`/`.vue` файлов — это чисто декларативный JSON.

## Верхний уровень (`MenuSettings`)

| Поле | Описание |
|---|---|
| `$schema` | Относительный путь до `menuSettings.schema.json`. |
| `Uid` | Свежий UUID v4. |
| `Name` | Технический идентификатор (`snake_case` латиницей, ≤30 символов) для **новых** меню. Используется в URL-маршрутах конструктора. |
| `Title` | Метка (любой язык). |
| `Memo` | Короткое описание (по-русски). |
| `IsActive` | Только активные меню участвуют в боковой панели. По умолчанию `true`. |
| `Version` | Счётчик версии; начинать с `1`. |
| `Items` | Массив `MenuSettingsGroupItem` — корневые записи (группы, top-level ссылки, разделители). |

## Четырёхуровневая иерархия

```
MenuSettings
└── Items: MenuSettingsGroupItem[]       // корневые записи: группы / top-level ссылки / разделители
    └── Items: MenuSettingsColumn[]      // колонки внутри группы (рендерятся бок-о-бок)
        └── Items: MenuSettingsSubItem[] // заголовки колонок со списками ссылок
            └── Items: MenuSettingsLinkItem[] // конечные ссылки и разделители
```

Колонки одной группы рендерятся **горизонтально друг рядом с другом** внутри MegaMenu-попапа. Каждая колонка содержит одну или несколько озаглавленных подсекций.

## Корневые записи — `MenuSettingsGroupItem`

Три вида, по полю `Kind`:

| `Kind` | Имя | Назначение |
|---|---|---|
| `1` | `Link` | Самостоятельная top-level ссылка (без вложенных колонок). |
| `2` | `Separator` | Визуальный разделитель между корневыми записями. |
| `3` | `Group` | Группа с вложенными колонками/подгруппами/ссылками. **Дефолт для новых записей.** |

| Поле | Описание |
|---|---|
| `Uid` | Свежий UUID v4. |
| `Kind` | `1`/`2`/`3` (см. таблицу). |
| `Title` | Метка. Игнорируется для `Kind = 2`. |
| `IconClass` | CSS-класс ведущей иконки. Использовать [PrimeIcons](https://primevue.org/icons/) (`"pi pi-folder"`). Можно `""`. |
| `Url` | URL цели. **Только для `Kind = 1`.** Поддерживаются hash-routes. |
| `IsVisible` | Невидимые записи пропускаются. По умолчанию `true`. |
| `AutoFill` | `true` — авто-заполнение группы по виду метаданных. **Только для `Kind = 3`.** По умолчанию `false`. |
| `MetaObjectKindUid` | `Uid` вида метаданных, объектами которого заполнить группу. **Обязательно при `AutoFill = true`.** Иначе `""`. |
| `ItemsPerColumn` | Сколько объектов на колонку в авто-режиме. По умолчанию `10`. |
| `Items` | Массив `MenuSettingsColumn`. Редактируется вручную в manual-режиме; **игнорируется** в auto-fill (использовать `[]`). |
| `MetaObjectKindUidParsed` | Вычисленная GUID-форма `MetaObjectKindUid`. **Управляется сервером** — присутствует в экспортах. Для новых записей ставить тем же значением что `MetaObjectKindUid`, или `"00000000-0000-0000-0000-000000000000"` когда `MetaObjectKindUid` пуст. |

## Колонки — `MenuSettingsColumn`

Простая обёртка для вертикальной колонки внутри группы.

| Поле | Описание |
|---|---|
| `Uid` | Свежий UUID v4. |
| `Items` | Массив `MenuSettingsSubItem` — подсекции внутри колонки. |

## Подгруппы — `MenuSettingsSubItem`

Подсекция внутри колонки: заголовок + список ссылок.

| Поле | Описание |
|---|---|
| `Uid` | Свежий UUID v4. |
| `Title` | Заголовок над списком ссылок. |
| `IsVisible` | Невидимые подсекции пропускаются. По умолчанию `true`. |
| `Items` | Массив `MenuSettingsLinkItem` — сами ссылки. |

## Ссылки — `MenuSettingsLinkItem`

Конечный лист — кликабельная ссылка или горизонтальный разделитель:

| `Kind` | Имя | Назначение |
|---|---|---|
| `1` | `Link` | Кликабельная ссылка. |
| `2` | `Separator` | Горизонтальный разделитель. |

| Поле | Описание |
|---|---|
| `Uid` | Свежий UUID v4. |
| `Kind` | `1` или `2`. |
| `Title` | Текст ссылки. Игнорируется для `Kind = 2`. |
| `IconClass` | PrimeIcons-класс иконки (`"pi pi-check"`). Можно `""`. |
| `Url` | URL цели. Только для `Kind = 1`. |
| `IsVisible` | Невидимые пропускаются. По умолчанию `true`. |

## Режимы заполнения группы

Корневая группа (`Kind = 3`) заполняется одним из двух способов.

### Ручной режим (`AutoFill = false`)

Автор пишет всё поддерево руками: `Items` (колонки) → `Items` колонки (подгруппы) → `Items` подгруппы (ссылки/разделители). Использовать, когда нужно курировать порядок/группировку/заголовки или когда ссылки ведут на кастомные view/отчёты/внешние URL без 1:1-соответствия виду метаданных.

В ручном режиме:
- `AutoFill = false`,
- `MetaObjectKindUid = ""`,
- `MetaObjectKindUidParsed = "00000000-0000-0000-0000-000000000000"`,
- `ItemsPerColumn = 10` (дефолт — нерелевантен в ручном, но поле оставляем).

### Авто-режим (`AutoFill = true`)

Сервер сам собирает содержимое группы из **всех активных** объектов выбранного вида метаданных, фильтрует по правам и раскладывает по колонкам по `ItemsPerColumn` штук. Каждая сгенерированная ссылка ведёт на `/app#/data-objects/{kindName}/{objectName}`.

В авто-режиме:
- `Kind = 3`,
- `AutoFill = true`,
- `MetaObjectKindUid` — `Uid` нужного вида из `project/metadata/system/kinds/kind.<kindName>.json` (например, `"032d8377-500f-4631-b435-1f7f69046674"` для `catalog`),
- `MetaObjectKindUidParsed` — то же значение,
- `Items = []` (сервер заполняет на лету; локальный контент игнорируется),
- `ItemsPerColumn` — настраивать под ожидаемое количество объектов (`10`–`30` — типично).

**Авто-режим — предпочтительный** способ выставить длинные списки справочников/регистров/операций, которые должны отслеживать изменения модели без ручной правки меню.

## Соглашения по URL

Поле `Url` принимает абсолютные URL, относительные URL и hash-routes BaSYS SPA. Типичные паттерны:

| Паттерн | Назначение |
|---|---|
| `/app#/data-objects/{kindName}/{objectName}` | Форма списка хранимого метаобъекта (catalog, operation, register, records). Пример: `/app#/data-objects/operation/task`. |
| `/app#/view-objects/customreport/{reportName}` | Кастомный отчёт. Пример: `/app#/view-objects/customreport/contract_statuses`. |
| `/app#/view-objects/customview/{viewName}` | Кастомный view. Пример: `/app#/view-objects/customview/all_tasks`. |

Если для существующего метаобъекта URL неочевиден — посмотри другую запись меню, ведущую на тот же вид, или открой объект в приложении и скопируй hash из адресной строки.

## Иконки

`IconClass` принимает CSS-класс [PrimeIcons](https://primevue.org/icons/) (`"pi pi-list"`, `"pi pi-folder"`, `"pi pi-check"`). Пусто (`""`) — без иконки. Выбирать иконки, визуально соответствующие назначению; одинаковые иконки для родственных записей.

## Создание нового меню

1. **Создать папку** `project/metadata/menu/{name}/` (snake_case латиницей, ≤30 символов).
2. **Создать settings-файл** `menu.{name}.json`:
   - `$schema` → `../../system/schemas/menuSettings.schema.json`,
   - свежий `Uid` (UUID v4),
   - `Name`, `Title`, `Memo`, `IsActive = true`, `Version = 1`,
   - `Items` — массив корневых записей.
3. **Свежие `Uid`** для каждой вложенной сущности (группа/колонка/подгруппа/ссылка). Каждый `Uid` уникален в пределах проекта.
4. **Заполнить `Memo`** на верхнем уровне (по-русски). У вложенных пунктов меню нет `Memo` — давать самоговорящий `Title`.
5. **Выбрать ручной или авто-режим** для каждой корневой группы (см. выше).
6. **`IsVisible = true`** на каждой записи, которая должна отображаться; `false` — скрыть.
7. У вида `menu` `IsReference = false` — запись в `system/dataTypes.json` **не добавлять**.

## Правка существующего меню

- Добавить ссылку → найти `MenuSettingsSubItem` (заголовок колонки) и допишь `MenuSettingsLinkItem` в его `Items`.
- Добавить заголовок колонки → дописать `MenuSettingsSubItem` в `Items` колонки.
- Добавить новую колонку → дописать `MenuSettingsColumn` в `Items` группы.
- Временно скрыть запись → `IsVisible = false` вместо удаления.
- Существующие имена меню/пунктов/файлов/папок (включая кириллические в `reference/`) **не переименовывать**.
- Переключение группы с ручного на авто — очистить `Items` (`[]`); локальный контент игнорируется в авто-режиме, но стаe entries вводят в заблуждение.
- Переключение с авто на ручной — очистить `MetaObjectKindUid` (`""`) и сбросить `MetaObjectKindUidParsed` в `"00000000-0000-0000-0000-000000000000"`.

## Гигиена

- Settings-файл должен валидироваться по `menuSettings.schema.json`.
- Каждая вложенная сущность — свежий уникальный `Uid` (UUID v4).
- `Title` — лаконичный (отображается в узких вертикальных колонках меню).
- Согласованное использование иконок: одинаковые иконки для записей одного типа ресурса.
- Примеры — в `reference/metadata/menu/`.
