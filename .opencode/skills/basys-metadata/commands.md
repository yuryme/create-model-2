# BaSYS Commands

Открывать при работе с программируемыми командами формы, кнопками, командами заполнения и файлами `*.command.*.bjs`.

## Базовые правила

- Тело программируемой команды хранить в `.bjs` рядом с JSON метаобъекта.
- В JSON ссылаться на файл через `Expression`.
- Не использовать npm-зависимости: runtime предоставляет BaSYS и JS-окружение платформы.
- При сомнениях сверяться с `basys-docs/ru/commands/programmableCommands.md` и `basys-docs/ru/commands/introduction.md`.

## Контекст команды

- `$h` - поля шапки формы.
- `$t.<table>` - табличные части формы.
- `$r` - текущая строка, если команда работает в контексте строки/таблицы.
- Доступные form-control функции уточнять по документации и работающим примерам.

## Эмпирика runtime проекта

- `$t.<table>` не полноценный `DataTable`; надежно использовать `.rows`, `.clear()`, `.load(...)`.
- После `save()` запрос к табличной части через `QueryBuilder` может вернуть stale-данные; актуальное состояние формы читать из `$t.<table>.rows`.
- Для `load()` ссылочная колонка обычно требует пару `<col>` и `<col>_display`.
- Stored-колонки с `Formula` после `load()` могут не пересчитаться автоматически; критичные значения заполнять явно.
- `alert()` может не показать окно; для ошибок использовать `throw new Error(...)`, для диагностики `console.log`.
- При отладке добавлять версионный маркер `console.log('VERSION', 'vN')`.
